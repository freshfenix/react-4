# Async Playground — навчальний React-проєкт

Невеликий інтерактивний приклад на React 19 і Vite, який демонструє читання значення `Promise` за допомогою `use()`. Кнопка запускає повторний запит із симульованою затримкою, а під час очікування React показує fallback через `Suspense`.

> Проєкт навчальний: дані генеруються локально в браузері. Реального сервера чи API-запиту тут немає.

## Можливості

- читання `Promise` у компоненті через React API `use()`;
- передавання Promise з батьківського компонента до дочірнього через пропс;
- fallback-індикатор завантаження за допомогою `<Suspense>`;
- повторне завантаження даних і відображення номера запиту;
- адаптивний темний інтерфейс з анімаціями.

Відкрийте термінал у каталозі проєкту `my-react-app` і виконайте:

## Як працює приклад

1. `App` створює Promise під час ініціалізації стану. `fetchMessage()` повертає його після затримки 1,1 секунди.
2. Promise зберігається у стані та передається в `MessageComponent` через пропс `promise`.
3. `MessageComponent` читає його результат за допомогою `use(promise)`. Поки Promise очікує на результат, компонент призупиняється.
4. Найближчий `<Suspense>` тимчасово показує fallback «З’єднуємося із сервером…», а після завершення Promise — повідомлення.
5. Кнопка «Надіслати ще раз» створює новий Promise і зберігає його у стані. Під час очікування кнопка блокується, а номер запиту оновлюється.

Promise створюється поза рендерингом `MessageComponent` і зберігається в стані батька. Це важливо: React має отримувати той самий екземпляр Promise під час повторних рендерів, поки не запущено новий запит.

## Навчальні нотатки

- `use()` — React API для читання ресурсу під час рендерингу, зокрема `Promise`. Для Promise, що ще очікує, компонент призупиняється; `Suspense` показує свій fallback.
- `Suspense` керує станом очікування, але не обробляє відхилені Promise. У цьому прикладі запит завжди успішний. Для реальних запитів варто додати Error Boundary для показу помилки й повторної спроби.
- Приклад спрощує роботу з даними для навчання. У production-застосунку слід використовувати рекомендований обраним React-фреймворком або бібліотекою підхід до завантаження, кешування та повторної валідації даних.
